# Clear Download Manager v1.0.0 UI and release preparation

## Goal

Finish the approved interface update for v1.0.0, deliver a standalone QA Windows executable to the user, and wait for their acceptance before publishing a production release or deploying the stable download link. Reuse and preserve the already-approved UI improvements in `artifacts/qa-redesign/Clear Download Manager QA.exe`; do not rebuild those parts from scratch. The later video-search and online-player optimization is a separate phase.

## User experience

### Navigation and icons

- Replace the current navigation icons with the user-provided assets for Downloads, Components, News, Settings, and theme switching (sun/moon).
- Preserve the provided assets' visual identity, remove baked-in backgrounds and fake selected-state treatments where present, and make only the designated blue artwork respond to the interface accent color. Icon backgrounds remain fixed and integrate with the app surface.
- Keep icon quality crisp while reducing shipped asset size with lossless compression. Keep the original source assets outside the application source tree, on the user's D: drive.
- Use the same compact selected-state treatment for Downloads, Components, and News. The indicator must be a small inset marker, not a full-width stripe. News retains the existing unread dot and gets a subtle pulse/glow only while an update is available.
- For selected navigation items and selectable controls, do not fill the whole control with the accent color or recolor its label. Keep the surface neutral; use the accent on the outline/compact selection marker and the icon. Other icons may use their existing accent-aware treatment.

### Theme and motion

- A theme change updates the whole app as one synchronized state; no intermediate frame may leave some sections in light mode and others in dark mode.
- Animate the sun/moon artwork during the switch and use a restrained glow/ring reveal centered on the theme control, matching the supplied keyframes. Button presses and switches receive short, subtle feedback.
- Respect `prefers-reduced-motion`; transitions become immediate or near-immediate when reduced motion is requested.
- Preserve the selected theme and accent through ordinary restarts, except for the one-time v1.0.0 preference reset below.

### Accent palette

- Set the first preset to blue `#24B8E8` and the second to green `#04D25A`.
- Keep the remaining presets in a visually coherent color order, removing no colors unless the current UI already has an explicit approved list change.

### Download rows and media preparation

- Keep download percentage as the primary progress figure; render downloaded/total size smaller and less prominent.
- Give the localized completion/remaining-time and date text enough width to show Spanish and English strings without clipping, without shrinking the preferred text size. Use concise translations if needed.
- Update relative dates when a download completes, without requiring a page refresh.
- In the multimedia preparation window, use the three supplied logos on fixed, interface-compatible backgrounds. Center all three at a consistent, moderate size; the destination icon must match its sibling in visual size and alignment. Only the blue interior artwork changes with the accent. Compress the shipped images losslessly.
- Improve the HTTP download document icon's contrast in light mode with a restrained outline; do not add a colored background.

### Update discovery and notice

- Check for app updates immediately after a normal cold launch when internet is available, then continue periodic checks with reasonable backoff while offline or failing.
- Discover component-catalog updates on startup, when connectivity returns, and periodically. Do not silently install or activate component updates.
- Surface available updates through News, with the existing unread dot and the subtle attention animation. Deduplicate the notice so one available version does not continuously re-alert after it has been viewed.
- Keep app-release updates and optional-component updates distinguishable in the notice details.

### One-time preferences reset

- On the first v1.0.0 startup, reset application preferences to the v1.0.0 defaults, including theme/accent and interface preferences.
- Do not delete, recreate, or reset download records, completed files, download history, queues, or user media/component data. Make the migration idempotent so it never repeats on later launches.

## Versioning and delivery gate

- Prepare the app as v1.0.0 and remove the Beta label from user-facing version identity.
- Provide a stable direct installer URL/name that can continue to point to the current release as versions advance; preserve versioned release assets for traceability.
- Build an isolated standalone QA `.exe`, following `scripts/build-local-qa-exe.ps1`, for the user to test before any production deployment or public v1.0.0 release. Keep the production installer as a later release artifact.
- Do not publish, deploy, tag, or replace the production stable download target until the user has tested the provided QA executable and explicitly accepted it.
- The later video-search and online-player performance work is out of scope for v1.0.0.

## Acceptance criteria

1. All replaced navigation icons match their intended states, remain crisp, adapt only their designated accent regions, and use compressed assets; source originals remain outside app code.
2. Selected navigation and selectable controls have neutral fills, readable neutral labels, restrained accent outlines/markers, and a compact selection indicator.
3. Theme switching is visually synchronized across the app, animates the sun/moon and subtle reveal, and honors reduced-motion preference.
4. The first two accent presets are exactly `#24B8E8` and `#04D25A`, in that order.
5. App and component update discovery run on cold start and recover from connectivity changes; News displays one clear notice per newly available update without installing components automatically.
6. The v1.0.0 preferences migration runs once and preserves all download/history data.
7. Version/build metadata and the stable installer-link mechanism are prepared, and a user-testable isolated QA Windows executable is produced before release/deployment.
8. The user reviews and accepts the QA executable before any public release or production deployment.

## Validation expectations

- Automated checks cover migration idempotence/data preservation, update-check scheduling/deduplication, theme state and reduced motion, and asset inventory/compression.
- Build the isolated QA executable and verify first launch, appearance switching, media/download display, update discovery behavior where QA endpoints permit it, and preservation of data in a copied test profile.
- Provide the `.exe` and a concise test checklist to the user. Treat their manual acceptance as a separate gate from build/test success.
- Resolve existing PR quality-check failures as part of implementation; do not claim the PR is ready while required checks fail.

## Open implementation detail

The exact reveal animation technique should be selected after checking the existing Tauri/WebView rendering and accessibility behavior. Keep the approved visual outcome and timing restrained; implementation may choose CSS masks, an overlay, or a synchronized theme-class swap if it avoids mixed-theme frames and respects reduced motion.
